# Brand Kits

Brand Kits belong to workspaces and customize experience previews. They do not recolor the Ruckus management app. Owners/Admins manage; Hosts/Viewers read. Settings are real PostgreSQL data. No Events or live brand publishing is included.

Each kit has stable identity, list metadata, soft deletion, a default flag and a non-null current revision. Each immutable revision stores name, validated config, canonical content hash, author and time. Updates lock and compare `baseRevisionId`; competing edits return `BRAND_CONFLICT`/409 and preserve the editor draft. No-op saves retain the revision. A deferred same-kit FK protects pointers. One active default is enforced by a partial unique index. The first kit becomes default; deleting a default picks the oldest remaining active kit, then UUID, or explicitly falls back to ordinary Ruckus styling when none remain. Switching defaults is serialized on the workspace row.

Config includes display name, primary/secondary/accent/surface six-digit hex colors, logo/background asset IDs, optional footer and required Ruckus attribution. Colors are stored uppercase. `showPoweredByRuckus` must be true; no white-label off switch is exposed. Names are bounded to 80 characters and footer to 160. The 50-active-kit safeguard is technical, unrelated to billing.

`BrandAssetStore` separates domain use from byte storage. `PostgresBrandAssetStore` uses bounded bytea rows now; later object storage can implement the same boundary. Accepted input: static PNG, JPEG and WebP. SVG/GIF/HTML/PDF/remote URLs are rejected. Magic bytes must match MIME. Limits: 2 MB logo, 5 MB background, 4096 pixels per edge and 16 million pixels total. Sharp decodes with fail-on-warning and bounded pixels, rotates orientation, strips metadata and emits WebP. Animation, malformed input and processing output over the limit are rejected. Per-workspace lifetime storage is capped at 100 assets/100 MB to prevent uncontrolled orphan uploads; retention cleanup is future operational work.

Assets are private. GET resolves session/membership and `brand.read`, then scopes the asset to the workspace. Responses use image/webp, nosniff, private revalidation, a content-hash ETag and restrictive CSP. No public URL, path or unauthenticated snapshot delivery exists. Brand writes verify every referenced image's workspace, type and availability. Historical references retain bytes: DELETE can retire an unused upload, but cannot delete an image referenced in any revision. Removing a logo/background in the editor writes null into the next kit revision; it does not damage history.

`brandContrast` calculates WCAG relative luminance/contrast; `readableForeground` chooses black or white for each solid background. Previews use those effective foregrounds without mutating selected colors. A warning explains low primary/surface contrast and the derived alternative. Image backgrounds stay decorative behind opaque text panels. Lobby, join/QR, leaderboard and winner previews are clearly labeled samples. QR opens the ordinary join page; sample code is not an active room.

`resolveBrandSnapshot` is a pure validated resolver. It returns a frozen transport-safe object tied to an immutable kit/revision with only presentation config and derived color pairs. Asset IDs remain private references, not public URLs. Phase 3 must create an intentional guest-safe immutable asset delivery/snapshot policy. No events, session history or persisted live snapshots are created here.
