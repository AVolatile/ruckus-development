# Production security and release review — Phase 6

Scope: local code/config/real PostgreSQL/Chromium review, October 16, 2026. No deployed service, DNS, SMTP account, managed database or physical device was inspected. This is not an independent penetration test, certification or claim of general production readiness.

## Fixed now

- Completed-history handoff persists in a narrow PostgreSQL queue; hash/UUID validation, bounded payload/claims/attempts, fencing, atomic materialization/audit and minimal deletion receipts protect integrity and retry safety.
- Owner/Admin deletion requires current transactional authorization and explicit confirmation, hard-deletes participant/segment detail, audits minimal metadata and prevents resurrection. Host/Viewer cannot delete.
- Readiness differs from liveness, gates new rooms/unsafe writes on incompatible schema and is false while draining. Explicit migration runner checks known hashes, rejects gaps/duplicates, uses a session advisory lock and bounded migration settings. Existing ledger entries are never rewritten.
- Startup rejects unknown environment modes, test/development DB crossover, weak/sample production secret configuration, unrelated production origins, unreviewed proxy settings and invalid worker/deadline/SMTP settings. Existing asset/body/rate constants remain bounded rather than introducing arbitrary configuration knobs.
- Application statements, locks, idle and total transactions have deadlines. Acquired-client error listeners handle server termination between awaited operations without uncaught process errors. Operational logs are field-allowlisted and API/socket DB errors do not return SQL/parameters.
- Native socket upgrades now share the explicitly reviewed loopback forwarded-address trust boundary; untrusted/oversized/malformed chains are ignored. Global plus room/IP join/resume limits account for shared networks. Bucket cardinality and lifetime are bounded.
- Signal handling is idempotent; post-disposal socket mutations are rejected during shutdown. Current-instance/capability broadcasts and run-identity completion callbacks preserve recycled-code isolation.

## Preserved controls reviewed

Exact Host/Origin/fetch metadata on unsafe cookie requests; no wildcard credentialed CORS; same-origin auth topology; explicit Secure/HttpOnly/SameSite=Lax host-only production cookies; database session revocation and library password/verification/recovery; normalized email and email-bound random-hash invitations; current workspace membership/role checks; Zod schemas and streamed auth/JSON/import/upload limits; raster magic/MIME/dimension/animation validation and WebP sanitization; private/no-store JSON, restrictive image delivery, nosniff/no-referrer/frame headers; quoted/formula-safe CSV including leading whitespace. No auth rewrite or player-account domain was added.

## Rate-limit review

Auth retains separate sign-in/signup/verification-recovery categories (20/8/5 per minute per IP); workspace APIs retain 300/minute/IP and separate actor/IP mutation/upload/invite controls. Socket creation remains 8/minute/IP. Join uses 300/minute/IP plus 60/minute/room/IP; resume 600 plus 120/room/IP. Inputs remain capability/engine validated rather than sharing the cloud API limit. Existing guest images have a distinct limit; CSV runs locally on one bounded fetched recap. Office NAT and provider proxy behavior need real pilot observation. Never trust arbitrary forwarded headers to work around throttling.
